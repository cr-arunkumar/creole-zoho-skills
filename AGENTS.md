# creole-zoho-skills — agent instructions

This repo packages **skills for automating Zoho Projects**, one skill per organisation, on top of a generic core.

When the user asks for anything involving Zoho Projects (tasks, titles, descriptions, comments, time logs, statuses, scores):

1. Read `skills/zoho-projects-core/SKILL.md` — org-neutral workflow and safety rules.
2. Identify the Zoho portal's organisation (`get_portals` → `org_name`) and read the matching org skill:
   - Creole Studios → `packs/creole-studios/skills/creole-studios-zoho/SKILL.md` (its `references/` hold the rules and scoring guide)
   - Other org → none installed; apply core rules only and offer to create one from `templates/org-skill/`.
3. Org rules override core defaults. **Never write to Zoho without a dry-run preview and explicit user confirmation**, and never write at all in read-only mode.

If the `zoho-skills` MCP server is connected, prefer its `zs_*` tools (`zs_org_rules`, `zs_lint_task`, `zs_build_title`, `zs_draft_task`, `zs_last_context`, `zs_save_context`): fetch the org's rules with `zs_org_rules` and preview writes via `zs_draft_task`; Zoho writes are gated by a preview token.

Zoho access is through the Zoho Projects MCP server (see `skills/zoho-projects-core/references/mcp-setup.md`).
Helper code is Python (stdlib; optional FastAPI + file-based SQLite in `api/`). Tests: `python3 -m pytest -q tests`.
`skills/` and `packs/*/skills/` are the source of truth; `.claude/skills`, `.agent/skills`, `.cursor/rules` are generated by `python3 scripts/build_adapters.py`.
